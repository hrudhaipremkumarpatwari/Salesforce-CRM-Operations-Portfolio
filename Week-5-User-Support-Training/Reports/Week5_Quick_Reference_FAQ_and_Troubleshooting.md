# Week 5 — Quick Reference, FAQ and Troubleshooting

> Simulated learning material; no live-org configuration or private screenshots are represented.

## Quick reference
| Need | First check | Safe next action |
|---|---|---|
| Cannot edit a field | Record access and field behavior | Capture exact error; escalate permissions issue |
| Record appears duplicated | Name, email/company, existing matches | Do not create another record until reviewed |
| Lead/case routed incorrectly | Routing inputs and required fields | Correct verified data or send to review queue |
| Report count looks wrong | Filters, date range, ownership scope | Re-run with documented filters |
| User cannot see a record | Ownership/sharing context | Escalate; do not broaden access casually |

## Troubleshooting flow
Issue reported → reproduce with non-sensitive example → classify data/access/process/reporting issue → collect evidence → attempt approved low-risk resolution → validate → document → escalate when permissions/configuration changes are required.

## FAQ
**Should a user create a new record when unsure whether one exists?** No. Search first and follow duplicate-review guidance.

**Should support change permissions to solve an urgent issue?** Only through the approved access/change process.

**What belongs in an escalation?** Business impact, affected function, reproducible steps, exact error, time, and actions already attempted.

**Are the examples proof of Salesforce administration experience?** No. They demonstrate training-oriented process understanding and support reasoning.
